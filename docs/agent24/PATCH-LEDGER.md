# Agent24 扩展与补丁清单

**当前产品基线**：上游 `v0.8.3`（`3e22822`），2026-10-18 经同步 PR #44 吸收（合并提交 `167d24c`，任务 #43），评估见 `BASELINE-EVAL-v0.8.3.md`；v0.8.2 时期的登记见 2026-10-16。下次吸收的入口是同步 issue #9（标题会随新正式版改写）。

**必须先升级的时点**（与 `UPSTREAM-BASELINE.json` 的 `current_baseline.upgrade_before` 一致）：
1. 开始第一个产品补丁的 task 分支之前（不是写完再判断）。产品补丁指改动或新增 fork 自有命名空间（`docs/agent24/`、`scripts/agent24/`、`.github/scripts/agent24-*`、`.github/workflows/agent24-*`）之外路径的任何工作，不论是否与上游改动相交。开 PR 时用 `git diff --name-only --no-renames origin/a24/develop...<补丁分支> | grep -v -E '^(docs/agent24/|scripts/agent24/|\.github/(scripts|workflows)/agent24-)'` 复核（`--no-renames` 不可省），输出非空就停下：先完成升级并合入 a24/develop，再 rebase。这条复核在当前基线落后于上游最新正式版时适用，同步 PR（head 为 `upstream-release`）不适用。
2. 导入任何非测试资料、或让开发者以外的人访问任何实例之前。
3. 任何对外制品出货之前。
4. 需要启用 `minio`、`langfuse` 或 `full` compose profile 时（设立时的理由：v0.8.2 钉的 quay.io MinIO 镜像已不能匿名拉取；v0.8.3 的 minio 改用 pgsty/minio，启用前仍按评估文档核对；默认 `STORAGE_TYPE=local` 不受影响）。

**重新评估**（不是必须先升级的时点）：上游发布影响当前基线的安全公告时，或到 2026-11-15 时，重新评估是否提前升级（David 负责；见 `upgrade_before.reevaluate_by` 与 `review_triggers`）。

**受测栈约束**：在 `.env` 里设 `WEKNORA_VERSION=v0.8.3`（`.env.example` 默认 latest，而 Docker Hub 的 `latest` 会随上游前进），每条 `docker compose` 命令前加 `env -u WEKNORA_VERSION -u COMPOSE_FILE -u COMPOSE_PROFILES -u COMPOSE_ENV_FILES -u COMPOSE_DISABLE_ENV_FILE`（不依赖 shell 状态），先用 `docker compose config --images` 核对解析出的镜像引用、用 `docker compose config` 核对 app 的 `STORAGE_TYPE` 为 `local` 和两个端口的 `host_ip` 为 `127.0.0.1`（过滤 `STORAGE_TYPE|host_ip|published|- mode:` 须正好七行、`published` 正好两个，多出映射或缺 `host_ip` 即停；项目根目录不得有 override 文件；只看这几项，完整输出含密钥，不贴进证据），再 `docker compose pull`，5 个默认服务的镜像都与登记的 digest 比对（RepoDigests 为空也算不一致）、不一致就停、不起栈，比对通过后再 `docker compose up -d --no-build`，起栈后核对各容器的 image ID（tag 被改指时的处理见评估文档）；不用 `start_all.sh`（`--no-pull` 也不行）；从 `3e22822` 本地构建时按评估文档的命令显式传版本参数、打 `v0.8.3-local` 标签，每条 compose 命令前同样加 `env -u WEKNORA_VERSION -u COMPOSE_FILE -u COMPOSE_PROFILES -u COMPOSE_ENV_FILES -u COMPOSE_DISABLE_ENV_FILE`，用 `docker compose config --images` 和 `docker compose config` 核对，只 `docker compose pull postgres redis`、这两个比对 digest 通过后再 `docker compose up -d --no-build`，起栈后核对 image ID（命令格式参照评估文档，镜像引用、digest、schema 版本以 UPSTREAM-BASELINE.json 的 current_baseline 为准），本地构建的 app、ui、docreader 改记源码 SHA、image ID、应用自报版本和构建参数；只用默认服务、`STORAGE_TYPE=local`（起栈后用 `docker exec WeKnora-app printenv STORAGE_TYPE` 留证，不是 `local` 就停栈），不启用 profile；误跑过 latest 的数据卷丢弃重建；`APP_PORT` 绑 `127.0.0.1:8080`，frontend 只需绑 `127.0.0.1`、端口任意，起栈后 `docker port` 不符、或按 compose 项目 label 过滤的 `docker ps -a` 不是正好 5 个默认容器（共享宿主机上别的容器不算）就停栈；Lite 与标准栈的结果不互相替代。命令格式参照评估文档，镜像引用、digest、schema 版本以 UPSTREAM-BASELINE.json 的 current_baseline 为准。
