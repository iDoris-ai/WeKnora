# ADR-001：Agent24 唯一主对话，WeKnora 专注知识服务

2026-10-11｜产品方向已由用户确认；本文记录二次开发决策，不表示接口已实现、工程验收通过或已排期。

关联：[跨仓约定 Agent24 #904](https://github.com/iDoris-ai/Agent24/issues/904)、[Line K #713](https://github.com/iDoris-ai/Agent24/issues/713)、[TODO-B 默认一站式知识库配置 #1](https://github.com/iDoris-ai/WeKnora/issues/1)。

## 背景与选择

普通个人或组织职员不应在 Agent24 和知识库之间选择两个机器人、重复登录或配置两套模型，更不应承担两份会话、记忆、任务状态和费用。知识库提供专业知识能力，主助理保持统一。

**迁移用户入口和编排权，复用知识流程；不整套搬运 WeKnora Agent 源码。**

- 不采用“内嵌完整 WeKnora 聊天”的方案：窗口内嵌不能解决两份对话权威。
- 不复制整套 Agent 引擎到 Agent24：避免重复运行时、记忆和模型配置，以及长期追踪上游的维护成本。
- 采用薄接口复用知识能力。上游 Agent 源码保留，集成模式不面向普通用户提供第二聊天入口；独立部署/开发验证模式与集成产品模式分开，不删除上游代码来实现隐藏。

## 权威与边界

| Agent24 负责 | WeKnora fork 负责 |
|---|---|
| 唯一主对话、会话历史、个人记忆 | 原件、解析、索引、检索、出处与知识版本 |
| 决定何时查知识和已授权范围 | 资料管理、Wiki、连接器同步与处理状态 |
| 模型出口策略、调用预算、审批、取消和审计 | 知识侧模型/任务调用执行与强制范围校验 |
| 汇总证据、生成主回答和受审 SOP 候选 | 必要时执行有界的深度知识子任务，保存获准发布的内容 |

主流程：**Agent24 收到问题 → 判断知识需求 → 检索/读原文 → 必要时深入查证 → 同一对话回答并显示引用。**

KnowledgeView 只承载资料、Wiki、来源/版本及任务管理。Wiki 可以在知识页被阅读、编辑并按权限发布，但对 Wiki 的提问、追问和跨任务协作仍回到 Agent24 主对话；不能换一个“知识助手”名称重开独立会话。

## 迁移流程，不复制控制面

先复用 REST search/read 等能力和已有解析/重排，再评估查询改写、多步检索与证据整理等流程。简单检索返回证据，由 Agent24 生成答案，不默认让两边各生成一次最终答案。

复杂检索可调用保留在 WeKnora 的执行器，但必须：

1. 绑定宿主已验证用户/组织、资源范围、用途、隐私、模型出口、deadline、trace 和宿主任务关联 ID；请求体中的模型生成字段不能作为身份或权限来源。
2. 限制步骤/token/时长和统一计费预算；后台检索若使用模型，也纳入同一任务的费用与出口控制。
3. 不维护第二份用户会话权威或个人偏好记忆；临时执行状态有明确生命周期，不通过 upstream memory 变成另一套长期记忆。
4. 不自主启用技能、浏览器、MCP、脚本/沙箱或跨应用执行。写入另走宿主批准范围；隐藏页面不是后端授权。
5. 返回带 resource/revision/locator 的证据、过程状态与 partial/error，支持宿主取消及断线后的关联状态查询。名称和 schema 待 #904 冻结，不声称已有对应接口。
6. 无法在后端强制限制时，不开放 Agent 执行端点，只开放获验收的检索/读取。

模型访问对用户是一套销售/激活方案，对服务端可以有不同技术调用路径；不强行让所有步骤使用同一模型，也不在客户端分享供应商根 Key。知识侧部署配置由受控方案管理，不让普通用户再配置一套供应商列表。复用 Agent24 身份也不等于传递宿主万能 token 或绕过企业身份验证。

## 安全与一致性

- 文档、Wiki 和子任务输出是有出处的资料/建议，不是系统指令，不得提升工具权限；提示注入负例必须验收。
- 撤权、组织/profile 切换、知识 Off 必须取消在途查询并重新验证范围；已有会话不能假称清除了已发送内容，敏感跨组织任务新建会话。
- LocalOnly 涵盖解析/OCR、Embedding、重排、生成和遥测；不能因“本地知识库”偷偷调用云模型。
- 个人偏好留在 Agent24 M1。组织背景、事实和 SOP 先形成候选，由有权人员确认后写入 KB；不默认复制所有聊天或覆盖人工修订。
- License、组织成员身份、资料处理许可与工具执行许可分别校验。自动优化不能自行加费、扩大范围、重建全部索引或删除原件。

## 分阶段验收

| 阶段 | 交付边界 | 完成证据 |
|---|---|---|
| KB-C0 设计与契约 | 本决策、跨仓职责、接口差异、owner/依赖登记 | 两仓文档与 #904 对齐；产品方向已确认，工程约定仍需评审 |
| KB-C1 主对话只读知识 | 授权样本 REST 检索/读原文、主回答、引用、取消 | 一个主会话走完检索→回答→回源；Off/撤权/取消/失败路径通过 |
| KB-C2 知识页无第二聊天 | 隔离 KnowledgeView、身份桥、管理/Wiki、回主对话入口 | 无额外注册/普通用户技术配置，无第二聊天历史；UI/API 权限及导航隔离通过 |
| KB-C3 有界深度知识流程 | 按需复用知识执行器 | trace/预算/出口/取消统一；执行与长期记忆负例通过，检索质量和重复生成成本有对照 |
| KB-C4 一站式与受审沉淀 | TODO-B 激活/2–3 问/幂等初始化、小型背景包、受审 SOP | 普通用户闭环和已有数据不被覆盖；语音复用授权能力，调优另列后续任务 |

这是验收拆分，不是日期、任务派发或硬性全串行：KB-C2 与一站式页面可在契约冻结后并行验证；知识执行器不是基本问答的前提。内网单用户 API/嵌入验证先行，Lite 分发/签名后补；两用户两组织、撤权、出口和恢复通过前不能宣称企业多人可用。

Agent24 侧同步维护 `docs/knowledge/ADR-KB-01-SINGLE-CONVERSATION.md` 与 `docs/agent/PLAN-KNOWLEDGE-CONVERSATION.md`，通过以 `ab/documenting` 为 base 的文档 PR 审查，并在 Documenting 的 Line K/W 登记衔接。David 的 Line K ownership 保留；宿主/销售服务新增职责待明确负责人，不默认为 David 全包。

## 非目标与维护

本次不实施 UI/Agent 修改，不修改用户已安装的正式版，不恢复 OD-M11/TPI-W/Line W，不声称 K1 全部完成或组织身份门已解除。专用知识页/REST 初期不以通用 Workspace 完成为前置；未来统一托管可另行评估。

与旧 T006 的通用 Workspace 顺序冲突时，本次用户确认仅修订首版知识接入顺序，不恢复其暂停任务；其它权限、资料权威和责任边界继续适用，冲突在 Agent24 文档 PR/#904 中记录。

保留 `upstream-release`/`upstream-main` 快进与 reviewed release merge。后续嵌入模式和有界执行适配保持独立补丁边界，每次上游升级同时验收“无第二对话”与既有知识功能；不以复制上游源码覆盖下游功能。
